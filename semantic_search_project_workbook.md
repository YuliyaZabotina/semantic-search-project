## 1. Заметки со встреч и контекст задачи

Компания CalmFruits хочет проверить, можно ли улучшить текущий поиск по каталогу товаров с помощью семантического поиска.

Основная проблема текущего лексического поиска заключается в том, что формулировка пользовательского запроса может не совпадать с текстом карточки товара. Пользователи могут использовать синонимы, разговорные формулировки, искать товар по назначению или указывать только часть его характеристик.

Задача проекта — построить MVP системы поиска типа `query-to-item`: на вход поступает текстовый запрос пользователя, а система должна возвращать топ-K наиболее релевантных товаров.

В рамках проекта необходимо:

- исследовать исходные данные;
- определить корректный объект поиска;
- сформировать текстовое представление товара;
- построить базовые варианты поиска;
- сравнить лексический и семантический подходы;
- оценить качество по разметке релевантности;
- провести эксперименты по улучшению;
- сформулировать выводы и рекомендации для бизнеса.

По итогам QA-сессии дополнительно уточнено:

- модель должна работать на уровне штрихкода;
- один штрихкод объединяет варианты одного товара разных размеров и цветов;
- в выдаче не должны появляться несколько одинаковых товаров только из-за разных размеров или цветовых вариантов;
- каталог для оценки качества формируется по `wb_products_dedup.parquet`;
- товары с пустыми значениями не исключаются из поиска;
- способ формирования текста для товаров с отсутствующим описанием необходимо определить в ходе проекта;
- не все признаки карточки товара должны влиять на семантическую выдачу;
- бренд не должен использоваться как признак для формирования семантического представления товара;
- категория и цвет могут использоваться, если помогают определить релевантность товара;
- окончательный состав `product_text` необходимо определить на основе EDA и дальнейших экспериментов.

## Вопросы к QA-сессии с заказчиком

### Вопросы об ограничениях системы, в том числе технических

- **Что известно:** в исходных данных один товар может быть представлен несколькими вариантами, отличающимися размером или цветом.
- **Вопрос/уточнение:** На каком уровне должен формироваться объект поиска, чтобы одинаковый товар не занимал несколько позиций в выдаче?
- **Ответ:** Модель должна работать по штрихкоду. Один штрихкод распространяется на варианты товара разных размеров и цветов, поэтому в поисковой выдаче должен присутствовать один товар, а не несколько его вариантов.

- **Что известно:** в проекте есть полный исходный каталог и отдельный файл `wb_products_dedup.parquet`.
- **Вопрос/уточнение:** Из какого множества товаров должна формироваться поисковая выдача при оценке качества?
- **Ответ:** Выдача при оценке качества должна формироваться по товарам из `wb_products_dedup.parquet`.

- **Что известно:** система должна работать как MVP семантического поиска.
- **Вопрос/уточнение:** Есть ли ограничения по времени ответа системы, используемой памяти и вычислительным ресурсам?
- **Ответ:** Не уточнено.

### Вопросы про бизнес-контекст

- **Что известно:** информация о товаре распределена между названием, описанием, категорией, цветом, брендом и другими признаками.
- **Вопрос/уточнение:** Все ли признаки товара должны участвовать в формировании поискового представления?
- **Ответ:** Нет. Следует использовать только те признаки, которые помогают определить смысл и релевантность товара.

- **Что известно:** бренд является точным атрибутом товара и может сильно влиять на точечные запросы.
- **Вопрос/уточнение:** Нужно ли включать `brand_name` в текстовое представление товара для семантического поиска?
- **Ответ:** Нет. Бренд не должен влиять на семантическую поисковую выдачу.

- **Что известно:** категория и цвет могут содержать важную информацию о товаре и встречаться в пользовательском запросе.
- **Вопрос/уточнение:** Можно ли учитывать категорию и цвет при формировании признаков товара?
- **Ответ:** Да. Категорию и цвет можно использовать, если они помогают определять релевантность. Необходимость их включения в `product_text` следует дополнительно проверить на данных.

### Вопросы про используемые для оценки метрики

- **Что известно:** задача представляет собой ранжирование товаров по соответствию текстовому запросу.
- **Вопрос/уточнение:** Какая метрика должна использоваться как основная для сравнения подходов?
- **Ответ:** Не уточнено.

- **Что известно:** каждому товару в разметке соответствует оценка `relevance` от 0 до 3.
- **Вопрос/уточнение:** Какие значения `relevance` считать релевантными при расчёте бинарных метрик?
- **Ответ:** Не уточнено.

- **Что известно:** система должна возвращать топ-K релевантных товаров.
- **Вопрос/уточнение:** Для каких значений K необходимо считать основные метрики?
- **Ответ:** Не уточнено.

### Вопросы про результаты работы системы

- **Что известно:** в исходном каталоге один товар может иметь несколько вариантов размеров и цветов.
- **Вопрос/уточнение:** Допустимо ли показывать в топ-K несколько вариантов одного и того же товара?
- **Ответ:** Нет. В выдаче не должны дублироваться одинаковые товары только из-за различий в размере или цвете. Объект поиска должен формироваться на уровне штрихкода.

- **Что известно:** у части товаров могут отсутствовать отдельные текстовые поля, в частности `description`.
- **Вопрос/уточнение:** Нужно ли исключать такие товары из поискового каталога?
- **Ответ:** Нет. Товары с пустыми значениями необходимо учитывать. Способ формирования их текстового представления нужно определить в ходе проекта.

- **Что известно:** итог проекта должен показать, помогает ли семантический поиск по сравнению с базовым подходом.
- **Вопрос/уточнение:** Какой результат будет считаться достаточным для принятия решения о дальнейшем использовании семантического поиска?

# Неделя 2. Базовый пайплайн поиска. Первое ревью

**Чекпоинт:** базовый пайплайн реализован и оценен, работа подготовлена к первому ревью.

## 2. План базового пайплайна

### 2.1. Формулировка задачи своими словами

Необходимо разработать MVP системы поиска товаров по коротким текстовым запросам в категориях "Одежда" и "Обувь". Для этого на основе исходного каталога сформируем текстовое представление каждой карточки и реализуем два подхода: лексический поиск на TF-IDF и семантический поиск по эмбеддингам. Качество решений сравним на единой обучающей разметке с помощью поисковых метрик. Для бизнеса такой поиск потенциально позволит улучшить соответствие выдачи запросам покупателей и упростить поиск подходящих товаров.

### 2.2. Подготовка данных

Для MVP выбраны категории "Одежда" и "Обувь", поскольку только они представлены в обучающей разметке. После фильтрации исходного каталога осталось 56 503 строки.

Дедупликацию выполнили по `imt_id`, выбирая строку с наиболее длинным непустым описанием. При совпадении длины описаний предпочтение отдавалось более длинному названию. Это позволило удалить 8 014 повторных строк.

Дополнительно исключены 113 карточек, у которых одновременно отсутствовали название и описание. При этом сохранены 30 289 товаров с заполненным названием, но пустым описанием.

Выполнена базовая очистка текстов: обработка HTML-сущностей, удаление HTML-тегов и нормализация пробелов. Для первой итерации выбран вариант B текстового представления: `subj_name` + `imt_name` + `description`, с объединением непустых полей через разделитель `" . "`. Бренд и цвет в базовый текст не включены.

Итоговый подготовленный каталог содержит 48 376 уникальных карточек. Пустых значений `product_text` нет. Средняя длина текста составляет 25 слов, медианная - 3 слова, что указывает на большое количество коротких текстовых представлений.

Для оценки дополнительно сформирован сокращенный каталог из 4 256 товаров, входящих в `wb_products_dedup.parquet`. Все 2 285 уникальных товаров обучающей разметки присутствуют как в полном, так и в сокращенном каталоге.

Отдельное поле со штрихкодом в предоставленных данных отсутствует, поэтому на данном этапе `imt_id` используется как доступный идентификатор для группировки вариантов товара.

### 2.3. Лексический поиск (baseline)

Реализован лексический поиск на основе `TfidfVectorizer` с униграммами и биграммами (`ngram_range=(1, 2)`) и ограничением словаря до 100 000 признаков.

TF-IDF-векторизатор обучен на полном подготовленном каталоге из 48 376 карточек. Получена разреженная матрица размером `(48376, 100000)`.

Для оценки дополнительно выделены строки матрицы, соответствующие сокращенному каталогу из 4 256 товаров. При этом исходный словарь и веса IDF сохранены.

Реализована функция `search_lexical(query, top_k=10)`, которая очищает запрос, преобразует его в TF-IDF-вектор и ранжирует товары по косинусному сходству.

Функция возвращает результаты в формате: `imt_id`, `imt_name`, `subj_name`, `score`. Корректность ее работы проверена сравнением с временной функцией поиска и просмотром выдачи для пяти обучающих запросов.

### 2.4. Семантический поиск

Для семантического поиска выбрана предобученная мультиязычная модель `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`.

На ее основе рассчитаны нормализованные эмбеддинги всех 4 256 товаров сокращенного каталога. Размерность эмбеддингов составляет 384, итоговая матрица имеет форму `(4256, 384)`.

Реализована функция `search_semantic(query, top_k=10)`. Запрос преобразуется в эмбеддинг той же моделью, после чего товары ранжируются по косинусному сходству. Формат результата совпадает с лексическим поиском.

Корректность соответствия текстов и сохраненных эмбеддингов проверена на трех карточках: при повторном кодировании сходство составило `1.0`.

Дополнительно изучена выдача семантической модели на тех же пяти запросах, что и у TF-IDF. В некоторых случаях модель выделяла отдельные характеристики, но не учитывала основной тип товара. Например, по запросу «кожаные сабо с открытым мысом» среди первых результатов оказались кожаные куртки и юбка.

### 2.5. Оценка качества

Сначала исследовано влияние набора кандидатов на оценку TF-IDF. Для этого зафиксированы 100 случайных обучающих запросов и рассчитана метрика NDCG@10 при поиске по полному и сокращенному каталогам.

На полном каталоге получено `NDCG@10 = 0.0710`, на сокращенном — `0.4561`. Среднее число размеченных товаров в топ-10 увеличилось с 1.16 до 8.41. При этом векторизатор, его веса и запросы оставались неизменными: менялся только набор доступных для поиска товаров.

На основании этого эксперимента для базового сравнения моделей выбран сокращенный каталог из 4 256 карточек. Он позволяет оценивать выдачу при существенно большем покрытии разметкой, хотя не устраняет проблему неполноты оценок полностью.

Для основного сравнения реализованы пять поисковых метрик:

- `Precision@10` — доля релевантных товаров среди первых десяти результатов.
- `Recall@10` — доля найденных релевантных товаров от общего числа релевантных товаров в разметке запроса.
- `MRR@10` — показатель позиции первого релевантного товара.
- `NDCG@10` — качество ранжирования с учетом исходной шкалы релевантности и функции полезности `2^rel - 1`.
- `HitRate@10` — доля запросов, для которых в топ-10 найден хотя бы один релевантный товар.

Для бинарных метрик зафиксирован порог `RELEVANCE_THRESHOLD = 2`. Проверка показала, что каждый из 700 обучающих запросов содержит хотя бы один товар с релевантностью не ниже `2`.

Функции расчета метрик предварительно проверены на искусственном примере. Основная оценка выполнена на всех 700 запросах `queries_train`, отдельно для двух моделей. Всего получено 1 400 строк результатов. Тестовая выборка в экспериментах второй недели не использовалась.

### 2.6. Результаты базового сравнения

По результатам оценки на всех 700 обучающих запросах получена следующая таблица:

| Метрика | TF-IDF | Семантический поиск |
|---|---:|---:|
| Precision@10 | 0.0741 | 0.0413 |
| Recall@10 | 0.2993 | 0.1325 |
| MRR@10 | 0.1622 | 0.1093 |
| NDCG@10 | 0.4328 | 0.1524 |
| HitRate@10 | 0.4271 | 0.2514 |

В текущем базовом сравнении TF-IDF показал более высокие значения по всем пяти метрикам. Наиболее заметное различие наблюдается по `NDCG@10`: `0.4328` против `0.1524` у семантической модели.

По `HitRate@10` значения составили `0.4271` и `0.2514` соответственно. Это означает, что TF-IDF нашел хотя бы один товар с релевантностью не ниже `2` примерно для 42.7% запросов, а семантическая модель — для 25.1%.

**Наблюдения по примерам запросов**

При визуальном сравнении выдачи обнаружены различия в характере ранжирования:

- Для запроса «бриджи зуавы» TF-IDF вернул преимущественно бриджи, а также товар с названием «Зуавы». Семантическая модель предложила худи, унты, босоножки и другие товары, явно не соответствующие запрошенному типу одежды.
- По запросу «кожаные мокасины» TF-IDF в основном находил мокасины, тогда как семантический поиск преимущественно возвращал товары с характеристикой «кожаный», включая куртку и юбку.
- Для запроса «кожаные сабо с открытым мысом» TF-IDF преимущественно предложил сабо. Семантическая модель выделяла отдельные характеристики запроса, но среди первых результатов оказались товары других категорий.
- Запросы с названиями брендов, например «топы cop copine» и «худи mego as», представляют отдельную сложность, поскольку поле `brand_name` не включено в базовое текстовое представление согласно требованиям проекта.

Эти примеры показывают, что выбранная семантическая модель не всегда сохраняет соответствие основному типу товара. Наблюдения согласуются с итоговыми метриками, но сами по себе не заменяют количественную оценку.

**Промежуточный вывод:** TF-IDF показал более высокое качество на текущем каталоге и обучающей разметке, поэтому его результаты будут использоваться как базовая точка сравнения в дальнейших экспериментах. Полученные показатели семантического поиска характеризуют конкретную предобученную модель без дополнительной настройки, а не возможности векторного поиска в целом.

### 2.7. Риски и открытые вопросы по итогам недели

**Неполнота разметки.** При поиске по полному каталогу многие результаты отсутствуют в оценках асессоров и технически получают релевантность `0`. Это может занижать поисковые метрики, поэтому основное сравнение проведено на сокращенном каталоге. При этом качество поиска на 4 256 карточках нельзя напрямую переносить на полный ассортимент маркетплейса.

**Короткие текстовые представления.** Медианная длина `product_text` составляет всего 3 слова. У части карточек тексты практически идентичны, например `Топы . Топы`, что ограничивает возможности различать товары как для TF-IDF, так и для семантической модели.

**Шаблонные и длинные описания.** В каталоге встречаются рекламные фрагменты и длинные тексты. Они могут снижать информативность представления товара, а при построении эмбеддингов часть текста может обрезаться из-за ограничения модели по числу токенов.

**Состав `product_text`.** В первой итерации использован вариант B без бренда и цвета. В дальнейших экспериментах необходимо проверить влияние допустимых дополнительных характеристик, в частности цвета.

**Уровень идентификации товара.** Дедупликация выполнена по `imt_id`, поскольку отдельный штрихкод в данных отсутствует. Соответствие выбранного уровня агрегации требованию QA остается открытым вопросом.

**Качество семантической модели.** В рассмотренных примерах выбранная модель не всегда учитывает основной тип товара и может отдавать предпочтение отдельным характеристикам. В дальнейшем необходимо проверить другие модели, состав и длину текста, изменяя по одному компоненту за эксперимент.

**Финальная оценка.** Все результаты второй недели получены на обучающей выборке и используются для диагностики и дальнейшей настройки. Тестовая разметка сохранена для однократной финальной проверки в конце третьей недели.
